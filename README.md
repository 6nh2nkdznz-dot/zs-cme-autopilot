# 中山医院继续教育平台助手

基于 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 的自动化脚本，用于
复旦大学附属中山医院远程继续医学教育平台（`elearning.zs-hospital.sh.cn`）。

在 **MuMu 模拟器**里通过**微信**打开平台，自动播放课程视频、处理播放中的
状态检测弹题、读取学习进度。

---

## 一、环境要求

### 必需

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 / 11（64 位） | 打包产物是 Windows x64 |
| 安卓模拟器 | **MuMu 模拟器 12** | 其他模拟器理论可用，但 ADB 端口与目录结构需自行确认 |
| 微信 | **8.0.79 或更新**（arm64 版） | **版本过低会登不上**，见下方「微信版本」 |
| adb.exe | 任意一份 | 程序会**自动探测**；找不到时在配置里写死 |
| 显示器分辨率 | 建议 1920×1080 或更高 | 模拟器要按 1080×1920 竖屏跑 |

### 不需要

* **不需要**安装 Python
* **不需要**安装 MaaFramework（已打包在内）
* **不需要**电脑上登录微信

### 微信版本（最容易踩的坑）

平台移动端**只认微信内置浏览器**，用模拟器自带浏览器访问会被重定向并提示
「手机端仅支持微信访问」。所以必须在模拟器里装微信。

装微信有两个坑：

**坑一：架构**。官网下载页给的「通用版」APK **只有 `armeabi-v7a`**，
而 MuMu 模拟器的 32 位能力是 `x86`，装了会闪退。
**必须用文件名带 `_arm64` 的版本**（纯 `arm64-v8a`），靠 MuMu 的原生桥接运行。

**坑二：版本**。官网下载页给的**不是最新版**。旧版本扫码后即使手机端确认了
也会被拦下来：

> 当前客户端版本过低，请前往应用商店升级到最新版本客户端后再登录。

权威版本清单看 [wechat-android-history-versions](https://github.com/DJB-Developer/wechat-android-history-versions)
（链接均指向腾讯官方 CDN）。**本项目验证过 8.0.79 可用。**

安装命令（下面的 `$adb` / `$addr` 用程序自带的探测得到，**不要写死路径**）：

```powershell
# 让程序自己找到 adb，并把结果打印出来
.\MaaElearning.exe --selftest
# 从输出里抄 [3/6] 那行的 adb 路径和 [4/6] 那行的地址，例如：
$adb  = "...\nx_device\15.0\shell\adb.exe"   # 用你自己的实际输出
$addr = "127.0.0.1:16384"

& $adb connect $addr
& $adb -s $addr install -r wechat-8.0.79-arm64.apk
```

## 二、首次使用步骤

### 步骤 1：启动 MuMu 模拟器

打开 MuMu 模拟器，等它进入桌面。

**端口不用你操心** —— 程序会自动向 `MuMuManager` 查询。想看的话：

```powershell
# MuMuManager 在模拟器安装目录的 nx_main 下
# 找不到就跳过，程序自己会探测
& ".\MuMuManager.exe" info -v all
```

在输出里找 `adb_port`。**默认 16384，多开时递增。**

### 步骤 2：在模拟器里安装并登录微信

按上面「微信版本」一节装 **arm64 的最新版**微信。

打开微信 → 点「登录」→ 用**手机微信扫码** → 手机端确认。

> ⚠️ 这一步必须人工完成，脚本无法代劳。

### 步骤 3：设置模拟器为竖屏

微信和平台移动端都是竖屏应用。用探测到的 adb 执行：

```powershell
# $adb / $addr 的取法见上面「微信版本」一节的说明
& $adb -s $addr shell "settings put system accelerometer_rotation 0"
& $adb -s $addr shell "settings put system user_rotation 0"
```

### 步骤 4：在微信里打开平台并登录

把下面这个地址发给微信的**文件传输助手**，然后在微信里点开：

```
https://elearning.zs-hospital.sh.cn/
```

在打开的页面里**用你的平台账号登录**。

> ⚠️ 这一步也必须人工完成。
> 用普通浏览器打开会看到「手机端仅支持微信访问」，那是正常的。

登录成功后应该能看到「我的学习」页面和课程列表。

### 步骤 5：（通常不需要）配置

**大多数情况下不用改任何配置。** 首次运行会自动生成 `data/config.json`，
其中 adb 路径和模拟器地址**默认留空 = 全自动探测**。

程序会自己找到：

| 要找什么 | 怎么找 |
|---|---|
| **adb.exe** | 与**正在运行的实例版本匹配**的模拟器自带 adb → Android SDK → PATH → 注册表 → 运行中的进程路径 → 各盘符目录扫描 |
| **模拟器地址** | 向 `MuMuManager` 查询所有实例的 `adb_port`（**多开也能覆盖**）→ 配置兜底 → `adb devices` |

**探测不假设安装目录**：MuMu 可以装在任意盘符，引擎目录
（`nx_device\12.0` / `15.0`）会随平台升级变化，多开时端口还会递增
（16384 / 16385 / …）。这些都靠实际探测，不靠猜。

每一步都会**真的验证**（跑得起来 `adb version` / 连得上 / 是真安卓设备），
验证通过才采用。

想看探测过程，或者自动探测失败了，单独跑这个：

```powershell
.\MaaElearning.exe --selftest
```

它会打印每个候选的来源和验证结果，例如：

```
[3/6] 自动探测 adb…
[detect] 运行中实例的 Android 版本: 15.0
[detect] adb 可用: ...\nx_device\15.0\shell\adb.exe  (来源: 运行中实例匹配)
[4/6] 探测模拟器端点…
[detect] ✓ 127.0.0.1:16384  PGBM10 1080x1920 @280  [MuMuManager/MuMu安卓设备]
```

#### 只有在自动探测失败时才需要手工填

**找不到 adb** —— 填完整路径（注意用双反斜杠）：

```json
{
  "adb": {
    "adb_path": "D:\\Android\\platform-tools\\adb.exe"
  }
}
```

**连不上模拟器** —— 填地址。端口从 `MuMuManager info -v all` 的
`adb_port` 字段读：

```json
{
  "adb": {
    "address": "127.0.0.1:16385"
  }
}
```

### 步骤 6：部署程序

把**整个 `MaaElearning` 文件夹**拷到目标机器。**不能只拷 exe** ——
`_internal` 里是 Python 运行时、MaaFramework 原生库、OCR 模型和自动化管线。

```
MaaElearning/
├── MaaElearning.exe      ← 双击这个
├── _internal/            ← 必须一起拷
├── data/                 ← 首次运行自动生成
└── debug/                ← 首次运行自动生成
```

## 三、日常使用

### 界面

双击 `MaaElearning.exe`（或源码运行 `python launcher.py`）会开一个窗口：

* **左栏**：环境状态（adb / 配置 / 连接 / 资源四项指示灯）、任务开关、按钮
* **右栏**：运行日志，按级别着色（错误红、成功绿、警告黄），可复制可清空

流程两步：**先「检查环境」** → 四项都变绿 → 再「开始运行」。

任务用**开关**而不是复选框：整门课轮播 / 每日签到 / 进入考核并答题 /
只看护当前视频（调试用）。

> 界面前身是普通 tkinter（灰扑扑的系统控件），现在换成了 `customtkinter`：
> 深色主题、卡片分区、圆角控件、状态灯。行为逻辑抽到了 `scripts/core.py`，
> 界面在 `launcher_ui.py` —— **换界面不影响自动化行为**，反之亦然。

### 命令行：跑单个工具

界面上只有 4 个常驻任务，但项目里还有很多**一次性工具**。
exe 内置了通用入口，不用装 Python 就能用：

```powershell
MaaElearning.exe --list                      # 看有哪些脚本
MaaElearning.exe --run run_exam_watch        # 看护一门课（全部课节）
MaaElearning.exe --run run_exam_watch --forget   # 忘掉本地进度，重看
MaaElearning.exe --run run_full_exam         # 跑完整卷并交卷
MaaElearning.exe --run harvest_answers       # 从结果页采集官方答案
MaaElearning.exe --run pending list          # 看待答题
MaaElearning.exe --run validate_pipeline     # 校验管线
MaaElearning.exe --run test_verify           # 校验层自测
MaaElearning.exe --selftest                  # 打包自检
MaaElearning.exe --classic                   # 用旧的经典界面
```

### 看课：跨运行记住进度

目录里**没有「已完成」标记**（实测，见 `course.py` 的 `is_course_complete`），
所以「哪节看过了」平台不给。整门课好几小时，一旦中断就得从头看。

所以本地记一份进度（`data/course_progress.json`），看护达标就写进去，
下次直接跳过：

```
[course] 本地记录已完成，跳过: 4吴琳-认知症的流行病学…
```

> **记录只是旁证，平台那边才是真的。** 如果某节实际去看了、拉进度发现
> 没达标，程序会**立刻撤销该条记录**并重看，不会一直错下去。
> 想全部重看：`--run run_exam_watch --forget`

### 出错了会自动回主页重来

用户指定的恢复策略：**识别到东西有误，就回主页重新看课**。

每节课开看前先校验「我还在课程页」；一旦发现页面不对（被弹窗顶掉、
误跳到结果页、点击没生效……），就退回「我的学习」列表重新走一遍导航。
已看过的课由上面的进度记录跳过，所以重来不会白看。

```
[recover] 识别出错 → 回主页重新来过
[recover] 第 1 次：按「学习」tab
[recover] tab 没到，改用 back
[recover] ✓ 退回 2 次后到主页
```

### 数据放在哪

exe 的数据在 **exe 同级的 `data/`**（题库、配置、日志）。

> **首次启动会自动接管旧数据**：如果你之前用源码版攒过题库，
> exe 启动时会往上找上层目录里的 `data/answer_cache.json`，
> 题库为空时自动搬过来，并在日志里打印搬运记录：
>
> ```
> [data] 已接管既有题库: 40 条
> [data]   D:\...\maa-elearning\data\answer_cache.json
> [data]   → D:\...\dist\MaaElearning\data\answer_cache.json
> ```
>
> **只在题库为空时搬，绝不覆盖已有的。**

### 运行前自检（换机器必做）

部署到新机器后，先跑一次命令行自检 —— 比开界面挨个点按钮快得多：

```powershell
.\MaaElearning.exe --selftest
```

它会依次验证 6 项：

```
[1/6] 检查打包路径…          资源包 / 管线 / OCR 模型 / 配置 / Agent 二进制
[2/6] 检查存图能力…
[3/6] 自动探测 adb…          与运行实例版本匹配的引擎自带 adb
[4/6] 探测模拟器端点…        MuMuManager 报的 adb_port，并连上去验证
[5/6] 加载资源与管线…        18 个管线节点 + OCR 模型
[6/6] 连接模拟器…            connected: True
```

每项打 ✓ 或 ✗，最后给总结论。**任何一项 ✗ 都先解决再往下走。**

> 第 6 项会真的去连模拟器，所以**跑之前要确保 MuMu 已经开着**。

### 正常流程

1. **确认 MuMu 模拟器已启动**并进入桌面
2. **确认模拟器里微信已登录**，且平台已登录（步骤 4）
3. **双击 `MaaElearning.exe`**
4. 点 **「① 检查环境」** —— 等日志出现「✓ 环境检查全部通过」
5. 勾选要执行的任务：

   | 任务 | 说明 |
   |---|---|
   | **整门课轮播** | 进入「我的学习」→ 打开第一门课 → **枚举整个目录 → 逐个播放，每个看完自动点下一节**；**全部学完会自动接着进考核** |
   | **进入考核并答题** | 单独跑考核入口（切「更多」→ 点「考核」→ 开始答题） |
   | **每日签到** | 课程页会自动弹签到弹窗，程序点掉并**确认签到成功**；已签到则跳过 |
   | **只看护当前视频** | 不切课，只看着当前正在播的这一个（调试用） |

6. 点 **「② 开始运行」**
7. 观察日志滚动。中途可以点「停止」中止

### 整门课轮播是怎么工作的

```
滚回目录顶部
   ↓
逐屏 OCR，解析出所有视频条目（标题 + 时长 + 屏幕位置）
   ↓
   ① 点条目标题区 → 切换课程
   ② 看护到学完（内含弹题处理）
   ③ 自动点下一条
   ↓
所有视频播完 → 结束
```

日志会长这样：

```
[course] 第 1 屏：识别到 6 条，新增 6，累计 6
[course] 第 2 屏：识别到 6 条，新增 4，累计 10
[course]  1. 4吴琳-认知症的流行病学与疾病轨迹进展.MP4  53:08
[course]  2. 5叶尘宇-BPSD的管理和照护者心理调适.mp4    60:40
...
[course] 目录共 10 个视频，开始逐个播放
[course] === [1/10] 4吴琳-认知症的流行病学与疾病轨迹进展.MP4 (53:08) ===
[watch] 进度 17.3% (7:26 / 43:02)
[watch] 检测到学习状态检测题，选 A 并提交
[course] ✓ 学完: 4吴琳-认知症的流行病学与疾病轨迹进展.MP4
[course] === [2/10] 5叶尘宇-BPSD的管理和照护者心理调适.mp4 (60:40) ===
```

**目录里没有「已完成」标记**（实测确认），所以程序不靠标记跳过，
而是顺序播放并自己记录本次运行内播过哪些。**中断后重跑会从头开始播** ——
因为无法从页面上得知哪些已学完。

### 运行期间必须注意

> ⚠️ **模拟器窗口不能最小化，也不能被休眠/锁屏挡住。**
> 安卓端在后台会暂停视频解码，进度就不涨了。

> ⚠️ **不要同时手动操作模拟器。** 你的点击会和脚本的点击打架。
> 切课是靠「点目录条目」实现的，你同时滚动目录会让它点错位置。

> ⚠️ **单个视频 45~60 分钟真实时间，整门课可能 8~10 小时。**
> 平台要求真实播放时长，快进无效 —— 这是平台的设计，脚本无法绕过。
> 可以挂着过夜，只要模拟器别被最小化或锁屏。

> ⚠️ **目录右下角有个蓝色 `+` 悬浮按钮**，会盖住最后一条。
> 程序把点击落点放在标题区（x≈200）并避开底部区域，已经绕开了它。

### 学完之后自动进考核

整门课全部播完达标后，程序会**自动**切到「更多」tab → 点「考核」→ 开始答题。

```
[course] 本门课是否全部学完: 是
[course] 本门课已全部学完，自动进入考核
[exam] 切到「更多」tab
[exam] 点「考核」图标
[exam] 已进入考核页（第 1 次点击命中）
```

**平台的硬门槛（实测确认）**：视频没学完时点「开始答题」会弹

> 请先完成课程视频学习，再进行考核！

所以「整门课轮播」没跑完时，考核这一步**进不去** —— 这是平台的设计，
不是脚本的问题。

「更多」面板是个 5 图标网格：

```
考核 (121,555)   笔记 (359,555)   课程答疑 (597,555)
签到 (121,737)   资料 (359,737)
```

> 注意：**微信消息横幅会飘在这个区域上方并吃掉点击**。
> 程序失败时会自动上滑收起横幅再重试，最多试三个位置。

> ⚠️ **答题的识别区域（题干区 / 选项区）需要按真实题目版式配置。**
> 目前还没拿到可进入的考核页样本，所以那部分坐标是**保守的占位值**。
> 没配准时程序会把拿不准的题**挂起等你作答**（见「答题工作流」），
> 不会瞎猜。

可以挂着去干别的，只要别让模拟器失去前台。

## 四、你会看到什么

### 日志里的关键行

```
[controller] connected: True                     ← 连上模拟器了
[resource] 已加载 18 个节点                        ← 管线加载正常
[resource] 自定义模块: ['VideoProgress', ...]     ← 自定义逻辑注册成功
[task] 进入我的学习 完成
[watch] 开始看护，目标 99.0%
[watch] 进度 17.3% (7:26 / 43:02)                ← 进度在涨
[watch] 检测到学习状态检测题，选 A 并提交          ← 弹题被自动处理
[watch] 弹题已处理
[watch] 已达标 99.2% (42:38 / 43:02)             ← 这门课看完了
```

### 弹题是怎么处理的

平台会在视频播放中插入「学习状态检测题」：

```
视频弹题（00:27:00）正确作答后继续视频学习
1、是否继续当前视频学习(此题为学习状态检测，如需继续学习，请选择A)（单选题）
   ○ A 是      ○ B 否
   [ 提交 ]
```

这道题的**答案写在题干里**，所以脚本可以安全自动作答。流程是
「选 A → 点提交 → 按钮变成『继续学习』→ 再点一次」。

**弹题会阻塞播放**，所以看护循环必须处理掉它，否则进度永远不动。

### 遇到不确定的题会停下来

如果出现**不是**状态检测题的弹题（题干里没有「请选择A」这类提示），
脚本**不会瞎猜**，而是：

* 把题目截图和 OCR 文本存到 `debug/pending/`
* 在日志里打印「转人工存证」
* 继续看护（不阻塞）

答题有及格线，猜错会把课挂掉，所以这里刻意保守。

### 2. 签到已经能自动完成（原先不行，已修）

之前记录为「点不动」，**现在解决了**。实测结论：

| 输入方式 | 结果 |
|---|---|
| `adb shell input tap` | ✗ 连点两次界面无变化 |
| **MaaTouch** | ✓ **一次命中** |

提交前后对照：

```
之前：本月连续签到0次，本月累计签到1次   按钮「立即签到」
之后：连续签到1次，本月累计签到2次       按钮「已经签到」
```

MaaTouch 是 MaaFramework 的默认 input 方式，所以只要走框架的
`post_click` 就能签上。程序还会用「次数有没有 +1」来**确认**结果，
而不是只看点击有没有发出去。

已签到时会自动跳过，不会重复点。

### 3. 「联网搜答案」—— 不再是主力了

原先设想的「搜题干找答案」实测**基本没用**：搜「老年认知症患者最常见的痴呆类型是」，
Bing 返回的是「老年人」百科、WHO 老龄健康页这类**泛化资料**，里面没有答案标记；
百度百科等站点还直接 403。

**但后来实测发现了一个更好的来源 —— 平台自己给答案。**

考核提交后的结果页会逐题显示：

```
您的答案：A
正确答案：D      ← 蓝色
答案解析: 暂无
```

这是**官方答案，零误差**。于是有了这个策略：

```
第一遍：随便答（反正答错不扣分）→ 提交
        → 从结果页读出全部正确答案 → 自动入库
第二遍：重做 → 题库 100% 命中 → 满分
```

工具已实现：`python scripts\harvest_answers.py`

实测采集一门 20 题的课，**20/20 全部拿到官方答案**。
代价只是「重做次数 +1」——而平台明确说客观题可重复提交。

所以现在是四级策略，联网降为最后的辅助：

```
1. 本地题库命中        → 直接用（零错误）
2. 从结果页采集官方答案 → 最可靠，推荐
3. 多路联网取证 + 投票  → 置信度 ≥ 0.75 才用
4. 挂起等人作答        → 落盘到 debug/pending/questions.jsonl
```

### 4. 无法加速

平台要求真实播放时长，快进无效。单门课 45~60 分钟，**必须有真实时间投入**。

## 五之二、答题工作流

答题是**人机配合**的，但主力手段已经变成「让平台自己告诉我答案」。

### 推荐流程：先采答案，再满分重做

```powershell
# 1) 进考核，随便答一遍并提交（答错不扣分，客观题可重复提交）
#    可以用工具自动答：
python scripts\run_exam.py --submit

# 2) 停在结果页，采集官方正确答案入库
python scripts\harvest_answers.py

#    输出示例：
#    [harvest] 采集到 20 题
#      1. [single] 答案 D   | 1、脓毒症患者达到血压目标后仍需监测的是
#     11. [judge ] 答案 F   | 11、中心静脉压可以准确反映右心室前负荷。
#    [harvest] ✓ 题库 0 → 20 条

# 3) 重做一遍，这次全部命中题库，应该满分
python scripts\run_exam.py --submit
```

### 平台规则（考核说明页原文，实测）

```
1、客观题考核可以重复提交。
2、主观题考核需要老师手动批改，批改前学生可以重复提交，批改后学生无法修改。
3、题库考核若包含问答题，其规则参考主观题规则，若不包含问答题，其规则参考客观题。
4、学生重复提交考核时，系统会记录重做次数。
5、建议上传考核文档不超过100M。
```

> ⚠️ 「重做次数」会被记录。所以别把它当儿戏反复刷 ——
> 采一轮答案、重做一次拿分，就够了。

### 低于阈值自动重做

`python scripts\retake_exam.py` 会把整条链路串起来自动跑：

```
循环（默认最多 6 次）:
    进入答题 → 逐题作答 → 补全遗漏 → 交卷
    → 读成绩 → 采集官方答案入库
    达标（默认 80 分）→ 结束
    不达标 → 下一轮
```

**关键：每轮结束都会采集官方答案。** 所以它是**收敛**的，不是靠运气重试：

```
第 1 轮：题库空   → 随便答 → 60 分 → 采集官方答案
第 2 轮：题库略满 → 混着答 → 65 分 → 再采
第 3 轮：题库够了 → 大部分答对 → 90 分 → 达标，结束
```

只重做不学习的话（比如单纯重试），重试多少次都一样。**学习才是关键。**

> **实测战绩**：这门课从 60 分起步，三轮跑到 **90 分**，题库从 0 攒到 40 条。

```powershell
python scripts\retake_exam.py --dry-run        # 只看当前分数与判定
python scripts\retake_exam.py                  # 自动跑到达标
python scripts\retake_exam.py --pass-score 90  # 自定义阈值
python scripts\retake_exam.py --max-attempts 2 # 限制重做次数
```

> 阈值判定会同时看「本次成绩」和「最高成绩」：历史已经达标就不再重做，
> 避免无谓地增加重做次数。读不到成绩时**保守地不重做**。

### 页面识别层

所有动作都先问「我在哪一页」，再决定做什么 —— 而不是各自猜。
这一层是踩坑之后补的：交卷成功后页面已跳到结果页，脚本却以为提交失败，
继续对着结果页「答题」，把「本次成绩：45分」当题干，而且**不报错**。

```powershell
python scripts\main.py --task "_页面探测"       # 管线侧：打出「页面=xxx」
python scripts\test_page_detect.py             # 脚本侧：26 项自测
```

命中页面包括：结果页 / 答题页 / 未选弹窗 / 考核入口 / 课程页。

### 试卷结构（实测）

```
一、选择题（单选）  第 1-10 题   选项 A/B/C/D
二、判断题          第 11-20 题  选项 T.正确 / F.错误   ← 不是 A/B！
每卷 20 题，每题 5 分，满分 100 分
截止倒计时 55 天（不是分钟级，没有时间压力）
```

> ⚠️ **题目和选项顺序都会变。** 实测两次考核：
> 题目是**从更大的题库里随机抽的**（两次只有约 45% 重合）；
> **同一道题的选项顺序也会被打乱**：
>
> ```
> 第 1 次  2、脓毒症…  A.体温 B.电解质   C.凝血功能 D.微循环指标
> 第 2 次  2、脓毒症…  A.体温 B.凝血功能 C.电解质   D.微循环指标
> ```
>
> **后果：答案不能只记字母。** 所以题库里每条都同时存了
> `labels`（采集时的字母）和 `answer_texts`（选项正文），
> 答题时按**正文**重新映射回当前页面的字母
> （`quiz.match_labels_by_text`）。
>
> 这也意味着**「采一轮就满分」是错的假设** —— 题库需要多轮累积才能覆盖。

### 另一种路径：拿不准就挂起

题库和联网都没命中时，题目会挂起到 `debug/pending/questions.jsonl`：

```powershell
python scripts\pending.py list             # 待答题列表
python scripts\pending.py answer 2 A C     # 作答（序号或缓存键都行）
python scripts\pending.py stats            # 题库统计
python scripts\pending.py export 题库.json  # 导出，可分享给同事
python scripts\pending.py import 题库.json  # 导入（人工答案优先）
```

### 命令一览

| 命令 | 用途 |
|---|---|
| `scripts\run_exam.py --dry-run` | 只识别不点击，核对题干/选项读得对不对 |
| `scripts\run_exam.py --submit` | 自动答完整卷并交卷 |
| `scripts\harvest_answers.py` | **从结果页采集官方答案入库**（推荐） |
| `scripts\retake_exam.py` | **低于阈值自动重做，每轮自动采集答案** |
| `scripts\fill_exam.py` | 补全遗漏未答的题（平台会逐题提示缺哪道） |
| `scripts\pending.py ...` | 待答题与题库管理 |

### 题型支持

| 题型 | 选项 | 处理 |
|---|---|---|
| 单选 | A/B/C/D | 题库 → 联网 → 挂起 |
| 多选 | A/B/C/D | 同上（置信度门槛更严） |
| 判断 | **T/F** | 同上，字母映射已适配 |
| 填空 / 简答 | — | **一律转人工**，无法可靠自动作答 |

## 六、排查问题

| 现象 | 原因与处理 |
|---|---|
| 自检第 3 项 ✗ 找不到 adb | 装 Android SDK platform-tools 并加入 PATH；或在 `data/config.json` 的 `adb.adb_path` 写死完整路径 |
| 自检第 5 项 ✗ 连接失败 | ① 模拟器是否已启动进入桌面；② `MuMuManager.exe info -v 0` 看 `adb_port` 是否与配置一致；③ 端口被别的程序占用 |
| 微信提示「当前客户端版本过低」 | 装的微信版本旧了。换 `_arm64` 的最新版（本项目验证 8.0.79 可用） |
| 微信装上就闪退 | 装成了「通用版」（只有 armeabi-v7a）。换文件名带 `_arm64` 的 |
| 打开平台显示「手机端仅支持微信访问」 | 用普通浏览器打开了。要在**微信里**点链接打开 |
| 视频进度不涨 | ① 模拟器是否被最小化/遮挡；② 是否弹了状态检测题没处理；③ 页面是否掉登录了 |
| 点击没反应 | 确认没有同时手动操作模拟器。合成事件和真人操作会互相干扰 |
| 日志里全是识别失败 | 先跑 `--selftest` 确认资源加载正常；再确认平台登录没过期 |

### 输出文件在哪

| 路径 | 内容 |
|---|---|
| `debug/snap/` | 运行期间的截图 |
| `debug/log/` | MaaFramework 详细日志 |
| `debug/pending/` | **需要人工确认的题目**（截图 + OCR 文本） |
| `data/config.json` | 生效的配置 |
| `data/answer_cache.json` | 本地题库缓存 |
